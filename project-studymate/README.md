# Project StudyMate — Build the Exam, Don't Just Read It

A hands-on companion to the domain notes. Instead of another set of flashcards, this
is **one program, built in 8 escalating levels**, using the real Claude API against
this repo's own study content. By the capstone you will have written: a tool-using
agent, a guarded quiz session with human-in-the-loop confirmation, a prompt-injection
drill you defended against yourself, an eval harness with tracing, an MCP server, and
a concurrent multi-agent orchestrator — and you'll have *used* it to actually study.

## Why this project, and why this shape

**The focus: Domain 2 — Applications and Integration (33.1%)** as the spine, because
it's a third of the exam and because building a real application is the one thing
that naturally pulls the other domains in as *decisions you have to make*, not facts
you memorize. Each level is a working increment of the same program:

> **single API call → give it a job → stream it → give it tools → give it judgment
> → make it safe → prove it works → ship it**

That escalation ladder is not arbitrary — it's the same one named in
[`capstone-production-grade-prompting.md`](../capstone-production-grade-prompting.md):
*single API call → workflow → agent*, extended two steps further into production
concerns (security, evals) and one step further into shipping (MCP, orchestration,
deployment). If you've read that capstone sheet, this project is you building the
thing it's describing.

## Setup (do this once)

```bash
cd project-studymate
pip install -r requirements.txt
```

Set your API key for the session (don't hard-code it anywhere — Level 6 covers why):

```bash
# PowerShell
$env:ANTHROPIC_API_KEY = "sk-ant-..."
# bash
export ANTHROPIC_API_KEY="sk-ant-..."
```

Level 8's MCP server needs one more package: `pip install mcp`.

## How to work through a level

1. Open `starter/levelN_*.py`. Read the module docstring at the top first — it
   explains *why* this level exists, not just what to type.
2. Fill in every `TODO`. Each one has a hint comment explaining the shape of the
   answer and, often, the specific trap it's testing for.
3. Run it: `python starter/levelN_*.py` (run from inside `starter/` so the sibling
   imports between levels resolve).
4. Stuck for more than ~15 minutes, or want to check your work? The finished version
   is in `solutions/levelN_*.py` — same filename, same function names, so you can
   diff your attempt against it directly.
5. Every script ends by printing a **CHECKPOINT** — a question to answer for
   yourself from what you just built, before moving on.
6. Then answer that level's 2 questions in [`checkpoints.md`](checkpoints.md)
   (blueprint-style, with an answer key) to convert the "doing" into something the
   exam actually asks.

Levels 5, 6, 7, and 8 **import your own code from earlier levels** (`import
level2_give_it_a_job as l2`, etc.) — finish the prerequisite named at the top of
each file first, or you'll hit the same `NotImplementedError` one level down.

## What's real vs. sandboxed

- `common.py` → `append_weak_area()` (used from Level 4 onward) writes to the
  **real** `../weak-areas.md`. This project doubles as an actual study tool — the
  weak areas you log while building it are weak areas you actually have.
- `sandbox/malicious_note.md` is a **contained, harmless fixture** for Level 6's
  injection drill only. It's never read by the real `search_notes` outside that
  one drill.
- `sandbox/session_state.json` and `sandbox/trace_log.jsonl` are generated by
  Levels 5 and 7 the first time you run them — safe to delete and regenerate.

## Cost note

Every level makes real, billed API calls once you fill in the TODOs and run it.
Nothing here is expensive (short prompts, capped `max_tokens`), but Level 8 fans out
several concurrent calls on purpose — that's the point of that level, not an
accident. Token usage is printed; price it at the *current* rate from
anthropic.com/pricing yourself (deliberately not hard-coded here — see `common.py`).

## After the capstone

- Diff your Level 6 tool descriptions and Level 8 MCP tool docstrings against the
  ones in `solutions/` — the wording of an exclusion condition is exactly the kind
  of thing the real exam tests as a scenario question.
- Add the two checkpoint questions per level (16 total) to a mixed practice set
  alongside the domain `practice-questions.md` files.
- If you build past the capstone on your own (multi-session memory, a second MCP
  tool, a real HTTP-transport deployment), that's no longer "studying for the
  exam" — that's just building a good side project. Keep going.
